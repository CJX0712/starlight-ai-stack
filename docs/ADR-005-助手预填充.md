# ADR-005: 用助手预填充消除思考型模型的推理泄漏

- 状态：Accepted（2026-09-20）
- 作者：晨星

## 背景

本机唯一的对话模型是 qwen3:4b（thinking 能力模型）。实测即使传 `think: false`，它仍会把推理过程写进 `content`，带来三个后果：

1. 答案前面一大段「首先，我需要仔细阅读用户的问题……」
2. token 预算被推理吃光，真正答案被 `num_predict` 截断
3. 单次问答耗时约 100 秒，且输出不可用

尝试过的无效手段：追加 `<arg_key:6124c78e>` 后缀（模型把它当正文回显）、`think: false`（字段生效但正文仍是推理）、提示词里写「不要分析」（无效果）。

## 决策

在 `build_messages` 末尾追加一条已经写好的助手消息，即**助手预填充**：

```python
{"role": "assistant", "content": "答案："}
```

模型只能从「答案：」之后续写，等于把推理段从输出里挤出去。同时保留 `strip_preamble` 作为后端不支持预填充时的兜底，且只在标记真的位于开头时才切（避免把模型复述指令的文本误当答案）。

## 实测对比（同一问题，同一机器）

| 方案 | 耗时 | 输出 |
|---|---|---|
| 无预填充 | 29.3s | 「首先，用户的问题是……」（推理泄漏，答案被截断） |
| 助手预填充 | 1.7s | 「健康检查地址是 /health。[1]」（干净，带引用） |

端到端问答耗时从约 100s/问 降到 3.7–13s/问。

## 后果

- 正面：答案干净、速度提升一个数量级、token 不再浪费
- 负面：预填充会固定输出前缀，若将来要结构化输出（JSON），需改为预填充对应的开头
- 防护：`tests/test_generator.py::test_messages_end_with_assistant_prefill` 锁死这条消息不能被删
