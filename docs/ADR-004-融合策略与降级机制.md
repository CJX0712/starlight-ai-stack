# ADR-004: 用 RRF 融合而非交叉编码器重排；模型缺失自动降级

- 状态：Accepted（2026-09-20）
- 作者：晨星

## 背景

两件事需要定调。

**其一，排序融合。** 常规做法是「召回 → cross-encoder 重排 → 重排顺序即最终顺序」。但交叉编码器一旦在查询语言上力不从心（典型如英文重排器配中文查询），会无人制衡地压掉正确答案；本机也拿不到可用的中文重排模型（bge-reranker 的 GGUF 在本机网络下不可达）。

**其二，模型可用性。** 配置里写 7B，不代表机器上真有 7B：网络慢会拉不下来，磁盘不够会失败，换机器更是什么都没有。此外可用内存不足时，7B 会让整机换页。

## 决策

1. **RRF 融合**：`score = Σ 1/(k + rank)`，稠密与稀疏两路互相制衡，任一路失手另一路仍能托住。重排接口位保留，将来接上 reranker 只影响 `retriever` 一层。
2. **两级自动降级**：
   - 模型缺失 → 按 `LLM_FALLBACKS` / `EMBED_FALLBACKS` 顺序挑本机可用模型，其次按能力标签（completion / embedding）兜底
   - 高配档内存不足（可用 < 4GB）→ 自动切 `balanced`
   - 所有降级原因写入 `notes`，通过 `/health` 暴露，不做静默降级

## 后果

- 正面：链路不会因为"配置写了但机器上没有"而崩；排查时有明确原因可查
- 负面：极端情况下用户拿到的不是自己配置的那档模型——这是有意的选择，**可用性优先于纸面一致性**
- 验证：`selftest` 的 `models` 项打印期望档位与实际生效档位及降级说明
