# ADR-003: 存储选 sqlite-vec + SQLite，而不是独立向量数据库

- 状态：Accepted（2026-09-20）
- 作者：晨星

## 背景

可选方案：Qdrant / Milvus（Docker 起服务）、Chroma / LanceDB（pip 装）、sqlite-vec（SQLite 扩展）。

约束条件：本机无编译器；内存长期被 Docker 容器与 WSL 占用（可用仅 1.7GB）；要求"干净环境可一键复现"。

## 决策

用 **sqlite-vec**（稠密向量近邻）+ **SQLite 表**（稀疏倒排、原文、元数据），全部落在同一个 `.db` 文件。

三个理由：

1. sqlite-vec 官方提供 `py3-none-win_amd64` wheel，无编译器也能装；实测 `sqlite_vec.load(conn)` 在 Python 3.13 上正常
2. 不需要额外起服务进程，内存占用为零，部署面最小
3. 知识库就是一个文件，备份迁移=拷文件，索引可随代码版本化

## 后果

- 正面：单机可跑、可拷贝、可复现；稠密与稀疏共用同一 rowid 空间，融合无需跨库对齐
- 负面：单机规模上限低于分布式向量库；向量维度写死在建表时，换嵌入模型需要重建向量索引
- 处置：维度不一致时 `pipeline.prepare()` 会捕获 `DimensionMismatch` 并按原文重建向量（原文始终保留，不丢数据）
