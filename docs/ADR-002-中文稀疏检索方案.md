# ADR-002: 弃用 SQLite FTS5，自建 BM25 倒排索引

- 状态：Accepted（2026-09-20）
- 作者：晨星

## 背景

稀疏检索最初打算直接用 SQLite FTS5（零依赖、自带 `bm25()` 打分）。实测结果否掉了这条路：

| 分词器 | 查询「检索」（二字中文） | 查询「向量数据库」 |
|---|---|---|
| `tokenize='trigram'` | **命中 0 条** | 命中 1 条 |
| 默认 `unicode61` | 命中 0 条 | 命中 0 条 |

trigram 需要至少 3 个字符才能组三角，而中文查询大量是二字词（检索、报销、退款）；unicode61 把整段中文当成一个 token，等于失效。

## 决策

自己实现 BM25 倒排表，存在 SQLite 里：`lexicon(term, df)` + `postings(term, rid, tf)` + `doclen(rid, len)`，查询时按标准 BM25 公式打分（k1=1.5, b=0.75）。

分词规则：中文取**单字 + 相邻二字组**，英文数字取整词。二字组让「检索」能命中长词中的子串，单字保证召回不漏。

## 后果

- 正面：二字查询可用，十万级块规模内性能足够，行为完全可控可测
- 负面：索引体积比 FTS5 大（存了单字和二字组），需要自己维护 df 与删除时的词项清理
- 验证：`tests/test_store.py::test_sparse_bm25_hits_chinese_two_char_query` 锁死了这个不变量
