# ADR-001: 模型后端选 Ollama，而不是自己编译 llama.cpp

- 状态：Accepted（2026-09-20）
- 作者：晨星

## 背景

目标机器是 Windows 11，实测**没有任何 C/C++ 工具链**（无 cmake、gcc、MSVC）。最初方案是下载 llama.cpp 官方预编译包（`llama-b11056-bin-win-cpu-x64.zip`），但实测 GitHub release 附件下载返回 `code=000`（连接失败），HF 上的 GGUF 模型也因 huggingface.co 不可达而拿不到。

## 决策

以**已安装的 Ollama 0.34** 作为本地推理后端，理由：

1. 自带预编译推理引擎与模型仓库，零编译、零配置
2. 机器上已有可用模型（qwen3:4b、nomic-embed-text），立刻能跑
3. 提供 `/api/chat` 原生接口与 `/v1` OpenAI 兼容接口，两条路都验证通过

同时保留 `OpenAICompatProvider`（走官方 openai SDK），把 base_url 指向 llama.cpp server / vLLM / 云端即可整层切换，上层代码不动。

## 后果

- 正面：装得上、跑得动、模型可增量拉取
- 负面：线程数等底层参数受 Ollama 约束（实测通过 `options.num_thread` 可锁线程，锁 4 线程最快）
- 中性：模型下载速度受网络限制，7B 档在大文件拉取时可能耗时数十分钟，因此必须实现模型自动降级（见 ADR-005）
