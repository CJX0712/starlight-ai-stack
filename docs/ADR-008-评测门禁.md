# ADR-008: 评测门禁用金标集硬阈值，指标必须可离线计算

- 状态：Accepted（2026-09-20）
- 作者：晨星

## 背景

"效果不错"不是验收标准。需要一个能重复执行、结果稳定的判据，回答三个问题：
检索召回够不够、答案是否命中要点、引用是否落到真实文本块上。

另外，评测本身经常变成一个黑盒：调用一堆框架，出个分数，没人说得清分数怎么算的。

## 决策

**指标全部是纯函数**（`eval.py`）：`contains_all` / `first_hit_rank` / `rank_to_rr` / `aggregate` / `gate`。
好处是指标定义的正确性可以用单元测试锁死（`tests/test_eval_metrics.py`），不依赖任何模型。

**中文匹配先归一化**：去掉全部空白再比。否则 `3 个工作日` 与资料里的 `3 个工作日` 命中、但模型输出的 `3个工作日` 会被误判为未命中——这类假阴性会让人误以为模型不行。

**关键词必须全部命中**才算该条通过：避免"碰对一个词就算过"的宽松判定。

**门禁是硬阈值，不是建议**：

| 指标 | 阈值 |
|---|---|
| ctx_hit@k（候选块含全部关键词） | ≥ 0.90 |
| top1_hit（首条即命中） | ≥ 0.60 |
| MRR | ≥ 0.70 |
| answer_hit（答案含全部关键词） | ≥ 0.70 |
| citation_valid（引用编号均落在上下文内） | = 1.00 |

不达标 → 进程非零退出。任何一条用例执行异常也直接判失败。

**CI 分工**：`unit` 任务每次提交都跑（无模型依赖，秒级）；`eval-gate` 放在手动触发，因为它需要下载约 1.5GB 模型，不适合挂在每次提交上，但需要时可一键复现并把报告作为产物上传。

## 后果

- 正面：效果回归可量化；改提示词或换模型后能立刻看出涨跌
- 负面：金标集只有 10 条、语料只有 5 篇，当前全绿说明的是"链路正确"而不是"效果优秀"。**扩充语料与用例是后续必须做的事**，阈值也应随语料规模上调
- 反面提醒：不要用小语料的高分对外宣称效果，那只是冒烟测试
