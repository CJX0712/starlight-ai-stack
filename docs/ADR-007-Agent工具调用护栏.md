# ADR-007: Agent 工具调用走"注册表 + 四道护栏"，并把工具交回给上层统一编号

- 状态：Accepted（2026-09-20）
- 作者：晨星

## 背景

要做的不只是"能调工具"，而是"调工具不会把系统弄崩"。真实风险有四类：

1. 模型可能连续调工具不停手，请求永远不返回
2. 某次检索卡住，整个 HTTP 请求被拖死
3. 工具抛异常，链路直接 500
4. 模型多次检索后答案里写 `[1]`，但两次检索的编号都是 `[1]` 起，引用会指错块

## 决策

**工具作为数据注册**：`ToolSpec(name, description, parameters, handler)`，新增工具不需要改 Agent 循环。当前内置四个：`knowledge_search`、`calculator`、`list_documents`、`current_time`。

**四道护栏**（缺一不可）：

| 护栏 | 实现 |
|---|---|
| 步数上限 | `max_steps`（默认 4，API 可调 1–8）；用尽后强制收口再要一次纯回答 |
| 单次超时 | 工具在独立线程中执行，`future.result(timeout=60)` |
| 异常收敛 | 未知工具 / 参数缺失 / 执行异常 / 超时，全部转成观察文本回喂模型 |
| 编号唯一 | 检索工具持有运行内计数器，第二次检索从 `[6]` 继续，绝不撞号 |

**计算器不用 `eval()`**：走 AST 白名单（数值、四则、幂、取模、少量数学函数），拒绝属性访问、调用任意函数、列表下标等。这是安全底线，不是洁癖。

**引用由上层统一处理**：工具只返回文本，命中的块通过回调交给编排层，最终答案的引用映射与落地校验复用 `generator` 的既有逻辑——避免引用逻辑在两条路径上分叉。

## 后果

- 正面：Agent 路径与问答路径共用同一套引用与落地校验；任何工具故障都降级为可读观察结果
- 负面：多了一层回调，`AgentRuntime` 与工具集必须共享同一个列表对象（已在 `build_agent` 中固化）
- 验证：`tests/test_agent.py` 用脚本化假模型逐个触发四条护栏；`selftest --module agent` 跑一次真实工具调用链路
